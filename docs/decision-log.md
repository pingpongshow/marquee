| D48 | 2026-10-01 | **Supersedes D36's segmenting.** FFmpeg writes one fragmented-MP4 stream (a fragment per keyframe, `frag_discont` for absolute timestamps) to a pipe, and the server cuts it into HLS segments along a plan. Files without an index are transcoded. | Accepted | The HLS muxer restarted timestamps at zero after a seek (AVPlayer can't cope) and its copy segments didn't match the playlist. | D56 | 2026-10-02 | Sonic analysis runs in a separate Python sidecar (`sonic/`) using the CLAP model `laion/larger_clap_general` on the GPU, with librosa for tempo, key and energy. The Go server keeps the embeddings in memory and builds radios, Sage, Adventure, similar and mixes itself | Accepted | CLAP puts audio and text in one space, so one model gives both "sounds like" and natural-language playlists (Sonic Sage) with nothing leaving the server. `larger_clap_music` was rejected: in transformers 4.57 its text and audio embeddings don't line up (prompt similarity ≈0.01). The sidecar listens on 127.0.0.1 only and mounts media read-only. It reports an analysis version (`model#n`) and bumping it re-analyses the library. |
| D57 | 2026-10-02 | Track energy (0–1) blends loudness (35%), rhythmic drive from onset strength (45%) and brightness from spectral centroid (20%) | Accepted | Loudness alone (the first version) barely varies across mastered music: everything landed between 0.48 and 0.72, so rules like "energy below 0.3" never matched. The blend puts ambient pads around 0.25 and beat-driven tracks around 0.7. Real music still bunches up (80% of the owner's library falls between 0.6 and 0.88), so smart-playlist rules compare energy as a percentile of the analysed library instead: "above 0.8" means the most intense 20%. |
| D58 | 2026-10-02 | Seek previews (trickplay) are JPEG sprite sheets of 10×10 tiles, 320 px wide, one tile per 10 s, made from keyframes only (`-skip_frame nokey`, `fps=1/10:round=up`) by a maintenance-window task that stops when the window closes and resumes the next night | Accepted | Keyframe-only decoding keeps it cheap, and NVDEC decoding (with `tonemap_cuda` for HDR) does a 100-minute 4K HDR film in 19 s versus 156 s on the CPU; the CPU path is the fallback. Each tile shows the last keyframe at or before its time, so previews are never ahead of where you'll land. About 3–7 MB per movie. The web player cuts tiles out of the sheets. For Apple players (whose AVPlayerViewController only shows thumbnails from HLS I-frame playlists), the same FFmpeg pass also writes an all-keyframe 320-px H.264 MP4 (one frame per 10 s, a fragment each); HLS master playlists advertise it as an `EXT-X-I-FRAME-STREAM-INF` with byte ranges per frame (AVFoundation then reports fast-forward support). Files played by direct play (no HLS) don't get them. |
| D59 | 2026-10-02 | Intros are found by matching Chromaprint fingerprints of the first quarter (at most 10 min) of each episode against its nearest episodes in the season; end credits by matching the last 5 minutes the same way, falling back to finding a long run of mostly-black frames near the end (the only method for movies). Detected markers are stored with source `detected`, and markers from Plex, the file or an admin always win | Accepted | The audio method is Jellyfin Intro Skipper's and needs no model. On the owner's library it found the openings of Severance, Ted Lasso and The Last of Us at the right places, but missed credits: their end-credit songs change every episode, so credits also use the look of a credits roll (white text on black is 90–100% near-black pixels). Fingerprints are cached on disk so new episodes compare cheaply, and episodes that found nothing are re-checked when their season gets new episodes. |
| D60 | 2026-10-02 | Collections are items of type `collection` with members in `collection_items`. Hiding single-film series matches Plex's default and keeps the Collections view useful. |
| D61 | 2026-10-02 | Webhooks post JSON (not Plex's multipart form) for playback.started/paused/resumed/stopped/watched and library.added, signed with HMAC-SHA256 in `X-Marquee-Signature` when a secret is set, from a bounded background queue with two retries. A full queue drops events rather than slowing playback. Stats on demand stay correct after Plex imports and need no extra tables; the queries take milliseconds at this library's size. |
| D62 | 2026-10-02 | Subtitle search uses the OpenSubtitles.com REST API (the owner's API key, optional account for more downloads) with IMDb/TMDB ids and the OpenSubtitles file hash; downloads are stored under `config/subtitles/<file>/` (media is mounted read-only) in `downloaded_subtitles`, and the scanner re-attaches them whenever it rewrites a file's streams | Accepted | Hash matches are subtitles timed for the exact file, so they sort first; machine-translated ones sort last. | D63 | 2026-10-02 | Local extras (LIB-8) are `video` items with `extra_type`, found in Plex/Jellyfin-style folders (Trailers, Featurettes, Behind The Scenes, Deleted Scenes, Interviews, Scenes, Shorts, Extras, Other) or by filename suffix (-trailer, -featurette…), linked after each scan to the movie or show whose folder holds them, and hidden from library lists, search, hubs and counts | Accepted | Keeping extras as ordinary playable items means playback, thumbnails and watch state work with no special cases. | D64 | 2026-10-02 | Offline downloads: originals are served as-is; "optimised" copies are converted on the server to HEVC MP4 (1080p 4.5 Mbps, 720p 2.2 Mbps, 480p 0.9 Mbps, never above the source bitrate), tone-mapped and with stereo AAC, one job at a time, kept a week. The iPhone/iPad app downloads with a background URLSession into Application Support (excluded from backups), plays from the device even when the server is reachable, and queues progress made offline for `PUT /items/{id}/progress` | Accepted | HEVC halves the size of H.264 and every supported iPhone/iPad decodes it in hardware. Converting one at a time keeps the GPU free for streaming. Offline plays still count (and leave the watchlist) once synced; stale offline positions never overwrite newer progress from another device. |
| D65 | 2026-10-02 | Guest DJ picks come from the server (`POST /music/dj`) using the sonic index: Stretch (closest sound by other artists), Groupie (the artist's other albums), Deep Cuts (the artist's least-played tracks for this listener), Contempo (closest sound within ±3 years); clients ask after every third of the listener's own tracks and mark picks in the queue. Web crossfade ramps Web Audio gains on the two alternating elements and skips consecutive tracks of one album | Accepted | Keeping the choice on the server makes every client's DJ behave the same and lets it use play history. | D66 | 2026-10-02 | Android phone, tablet and Android TV share one app (`android/`, Kotlin, Jetpack Compose, minSdk 26) that switches to a D-pad layout (side rail, focus rings, start focus on each screen) when the device has `FEATURE_LEANBACK`. | D67 | 2026-10-02 | Android Auto and Assistant use the music service's Media3 browse tree: For You (mixes, library, favourites and mood stations), Playlists, Artists and Recently Added. | D73 | 2026-10-02 | Watch together (SyncPlay): groups live in the server's memory; the state is playing/paused, a position and the server time it was true, with a version.
